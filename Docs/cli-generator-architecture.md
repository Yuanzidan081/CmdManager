# CmdManager 架构说明

## 1. 定位

CmdManager 是基于 PyQt6 的 Windows 桌面命令管理工具。它将可复用的命令文本定义为模板，基于模板创建带有差异配置的实例，再将实例按顺序组合为流程。

本文仅描述稳定的分层、数据模型和业务边界。控件布局、编辑表单和交互细节见 [详细设计](./cli-generator-detailed-design.md)。

## 2. 当前基础能力

当前版本已提供以下基础能力，后续重构应保持兼容：

- 分类、全局变量和 JSON 持久化。
- 命令变量 `%变量名%`、全局变量 `$变量名$` 的最终命令渲染。
- 命令预览、预览复制、单步终端运行。
- 命令编辑、复制配置、删除与同分类上移/下移排序。

## 3. 目标领域模型

### 3.1 Category

`Category` 继续作为模板和流程的一级归属，保留 `id`、`name`、`order`。

### 3.2 CommandTemplate

命令模板相当于“类”，定义可复用的命令结构：

- `id`、`categoryId`、`name`、`description`
- `template`：包含 `%变量名%` 与 `$全局变量$` 的命令文本
- `defaultVariables`：模板变量的默认值
- `revision`：每次模板保存后递增

模板中的默认变量用于统一维护所有实例共有的路径、参数和默认值。

### 3.3 CommandInstance

命令实例相当于模板的具体配置，可独立加入流程：

- `id`、`templateId`、`workflowId`（可为空）、`name`、`order`
- `templateSnapshot`：该实例最后一次同步后的模板文本与变量定义
- `templateRevision`：快照对应的模板版本
- `variableOverrides`：只保存与模板默认值不同的变量
- `pendingVariableKeys`：同步后需要用户确认的变量键

实例运行时以 `templateSnapshot` 为准：先应用模板快照默认值，再应用实例覆盖值，最后替换全局变量。这样模板修改不会立刻改变既有实例的实际执行结果。

### 3.4 Workflow

流程将多个命令实例按步骤组合：

- `id`、`categoryId`、`name`、`description`、`order`
- 实例通过 `workflowId` 关联到流程，并在流程内通过 `order` 排序

未设置 `workflowId` 的实例属于“未编排命令”，可单步运行但不能作为整组流程运行。

## 4. 模板继承与同步

模板保存后只更新模板本身及其 `revision`，不自动修改任何实例，也不因实例存在差异变量而报错。

实例卡片提供“同步模板”操作：

1. 将当前模板文本和变量定义写入该实例的 `templateSnapshot`。
2. 变量名仍匹配的实例覆盖值继续保留。
3. 新增、重命名后无法匹配的变量使用模板默认值；没有默认值时使用空值。
4. 这类变量写入 `pendingVariableKeys`，在实例编辑页以红色展示，直到用户确认或修改。
5. 同步完成后将实例的 `templateRevision` 更新为模板当前 `revision`。

同步入口仅放在实例卡片与实例编辑页，不提供模板修改后批量强制同步。

## 5. UI 架构

主界面保留分类 Tab；选中分类后使用双栏总览：

- 左侧为模板库，支持搜索、新增、编辑和删除；通过箭头可收起。模板可被添加到指定流程，或创建为未编排实例。
- 右侧为流程区，显示多个流程卡片。流程可展开，展示按顺序排列的实例卡片。
- 实例卡片显示名称、最终命令预览、同步状态、运行、编辑、上移、下移和移出流程等操作。
- 点击模板或实例的编辑操作进入统一编辑页；编辑页根据对象类型展示模板默认值、实例覆盖值与待处理字段。

SimplePerf 的推荐组织方式：创建 `record`、`pull`、`copyso`、`generate` 四个模板，再创建 `3new`、`3old`、`2` 三个流程，并为各流程添加相应实例。共有参数改模板，环境差异改实例覆盖值。

## 6. 服务层边界

| 服务 | 职责 |
| --- | --- |
| `TemplateService` | 模板增删改查、变量解析、版本递增、引用检查。 |
| `InstanceService` | 实例创建、变量覆盖、模板同步、预览构建、实例排序。 |
| `WorkflowService` | 流程增删改查、实例编排、单步与整组流程运行。 |
| `GlobalVariableService` | 全局变量的维护、检索和替换数据提供。 |
| `JsonBase` / `TerminalBase` | 新旧数据读写、Windows 终端启动。 |

最终命令构建必须在服务层单点完成，顺序为：实例快照/默认值与覆盖值合并 → `$全局变量$` 替换 → `%命令变量%` 替换 → Windows 引号与转义处理。UI 不直接拼接命令或修改排序字段。

## 7. 流程执行

每个实例保留单步运行按钮。流程头部额外提供“运行流程”：

1. 运行前让用户选择“失败即中止”或“失败后继续”，默认选择中止。
2. 在同一个新开的 cmd 终端中，按照流程实例的 `order` 顺序执行。
3. 中止模式使用失败短路连接；继续模式记录失败但继续执行后续步骤。
4. 每步在终端输出名称，便于定位失败步骤；本期不支持持久化跳过步骤。

## 8. 数据迁移与兼容

- 首次读取旧结构的 `commands.json` 时，先创建带时间戳的原文件备份。
- 按命令 `template` 去重生成 `CommandTemplate`；原命令转换为引用该模板的 `CommandInstance`，其变量值转换为覆盖值或快照默认值。
- 自动迁移不推断业务流程，迁移后的实例初始归入“未编排命令”；用户再手工创建 SimplePerf 等流程。
- 读取阶段继续兼容旧的 `categories`、`commands`、`globalVariables` 结构；迁移完成后的保存写入新结构。

## 9. 验收标准

1. 相同命令文本的历史命令只创建一个模板，变量差异保留在实例。
2. 模板修改后，未同步实例的预览与运行结果不变；单个实例同步后正确继承模板更新。
3. 无法匹配的同步变量使用默认值或空值，并在实例编辑页显示红色待处理状态。
4. 模板可添加到流程，流程内实例可排序并在重启后保持顺序。
5. 单步运行与流程运行均使用相同的最终命令构建逻辑；流程可按运行前选择的失败策略执行。
6. 旧数据自动备份并可迁移；分类、全局变量、预览复制等既有能力保持可用。
